# Value Tuning

スライダーや回転式のピッカーで、数値を狙った値に合わせる方法。アプリに依らず使える。アプリごとの目盛りの大きさは `apps/<app>/` に書く。

## スライダー

### 動かし方

- `left_click_drag` を、つまみから離れた位置（左か右の端の近く）から始め、つまみを越えて狙う位置で離す。つまみはほぼ離した位置で止まる
- ずれは向きとつまみの大きさで変わる。右向きは離した位置より数〜20px 手前、左向きは数〜10px 奥に止まることが多い
- 狙う位置がつまみの左にあるときは右端から左へ、右にあるときは左端から右へ引く

### 効かない操作

| 操作 | 結果 |
| --- | --- |
| タップ | その位置へ飛ばない |
| つまみの上から始めるドラッグ | 動かないことが多い |
| 約 50px 未満の短いドラッグ | 無視されることが多い |
| マウスを押したまま `mouse_move` で動かす | 動かないか、逆向きに動く |
| 小数の座標 | 整数に丸められる（1px より細かくは動かせない） |

### 狙った値に寄せる手順

1. 1回目は目分量で動かして保存し、実際の値を読む（画面の表示か、機器の API）
2. 2回目で別の位置を試し、2点から「1px あたりの変化量」を出す
3. 目標との差 ÷ 変化量 で終点を何 px ずらすか決め、1px 単位で寄せる
4. 1px で動く量より細かくは合わせられない。目標を挟む2つの値が出たら、目標に近い方を選んでユーザーに伝える
5. 画面を開き直すとスライダーが既定の位置に戻るアプリでは、毎回すべてのスライダー（明るさなど目標でない値も）を合わせ直す

### 目盛りが分からないとき

- % や K が画面に出るスライダーは、動かすたびに zoom で読む
- 出ないものは、保存後の一覧の説明文か、API・機器の実測で読む
- ミラーリングのウインドウを大きくする（View → Larger）と 1px あたりの変化量が小さくなるが、座標の測り直しが要る

## 回転式のピッカー（時刻など）

- 選択行のすぐ上か下の行をタップすると、1つずつ送れる。送る回数だけタップを並べ、最後に zoom で確かめる
- ドラッグでは回らない
